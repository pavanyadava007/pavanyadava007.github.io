## Problem & constraints

Most model-compression write-ups stop at the conversion script. The question this project was
built to answer is the one that actually decides a release: *given a measured accuracy loss, does
this artefact ship, and what happens to 20 devices if it is wrong?*

So the constraints were process constraints rather than model constraints. Every candidate has to
pass a fixed gate set before it can be signed. Every bundle is signed and verified on the device
before the swap. The rollout is staged with health windows and can be aborted from outside. And a
second inference path in a different language has to agree with the first to box-level IoU > 0.99,
so that "it works in Python" is not the only evidence.

## Results

The rollout numbers are the ones I trust most, because they were measured against 20 live agents
over real MQTT rather than simulated: a full **5% → 50% → 100% canary in 90.6 s with 0 failures**,
and an abort that reverted every switched device in **4.7 s**. Running that repeatedly surfaced a
real bug - a canary false-positive caused by post-swap cold-start latency being counted as a
health failure - which is the kind of thing that only appears when you actually do the rollout.

The Rust runtime reached **-20% RSS** (134.8 vs 168.7 MB) on the same `.so` and the same model,
with a 109 ms cold start, and is CI-gated against the Python path so the two cannot drift.

## Ablations

The compression result is a negative one and it is the most useful thing in the project.

INT8 post-training quantization does what it is supposed to do on size: **10.61 MB → 3.17 MB**,
a 3.3x reduction. On this AMD EPYC 7R13 it also made inference about **3 ms slower** (QDQ
overhead) and cost **4.6 points of mAP@0.5** (0.569 → 0.523). Both INT8 points sit below and to
the right of their FP32 counterparts, so the Pareto front on this CPU is the two FP32 builds.

INT8 still ships - but for exactly one reason, stated plainly: a 3.3x smaller artefact to push
over the air to 20 devices. On a device with INT8 acceleration the trade would look different,
and there is no such device here, so no such claim is made.

Three other compression routes were tried and none shipped. Quantizing the head's final `Concat`
produced **mAP 0.000**, because box coordinates and class probabilities cannot share one uint8
scale. QAT was blocked by torch 2.6 removing `prepare_qat_fx`. Structured pruning found **0
prunable groups** on YOLO11, and distillation came in at 0.6835 against a 0.6878 baseline - no
gain, not shipped.
